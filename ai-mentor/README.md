# 引路人 · AI 导师

> 一个用来替代导师做**重复性新人培养工作**的小工具。
> 定位不是"问答机器人"，而是**培养流程的执行者**。

- 纯 Python 标准库 + 原生前端，**零安装、零构建**
- 一条命令启动，浏览器打开就能用
- 不接大模型也能用（退化为"带出处的知识检索"），填个 API Key 就自动升级
- 所有知识都是纯文本文件，**导师自己能改、能 review、能追溯**

---

## 1. 三分钟跑起来

```powershell
cd ai-mentor
python server.py
```

然后浏览器打开 **http://127.0.0.1:8848**

换端口 / 让同事访问：

```powershell
python server.py --port 9000
python server.py --host 0.0.0.0      # 同一局域网内其他人可访问
```

Windows 上也可以直接双击 `start.cmd`。

想重置所有运行数据（问答记录、进度、沉淀池）：

```powershell
Remove-Item data\runtime -Recurse -Force
```

### 双端登录：新人端与导师端是两个页面

- **新人端** `http://127.0.0.1:8848/` —— 问答 / 任务 / 周报 / 地图 / 陪练 / 自检 / 档案
- **导师端** `http://127.0.0.1:8848/mentor.html` —— 导师看板 / 任务发布与确认 / 知识库 / 设置

两端各登各的账号：登录页只显示本端角色的账号，服务端对导师专属接口（看板、发布、确认、
FAQ 管理、设置）做角色校验，新人账号调用一律 403。角色在 `data/users.json` 的 `role`
字段配置（`mentor` / `newcomer`），配 4 位 `pin`：

### 项目知识库：导入项目，AI 自动生成专属知识

导师端「项目知识库」卡片：填项目名 + 上传代码/文档 → 系统自动生成该项目专属知识库
（项目概述、需要的软件环境与依赖、目录结构、上手注意事项），知识条目带项目归属。

- **各项目互相独立**：卫星项目的知识不会混进其他项目；通用知识（公司 WiFi、报销流程）不受影响
- 新人端问答页选择「知识范围」后，回答优先命中所选项目的知识库
- 未接入大模型时生成资料清单 + 依赖线索的保底版本，接入后为 AI 深度生成
- 导师发布任务时可用 **✨ AI 起草**：粘贴需求描述，自动填好标题/说明/子项，改一改就能发

### 可选：关闭身份保护

默认全员配了 `pin`，即登录模式。如果想要免登录的荣誉制（选个身份就能用），
把 `data/users.json` 里所有人的 `pin` 删掉即可：

```json
{ "id": "chen_sy", "name": "陈思远", "track": "engineering", "cohort": "2025 春招", "pin": "2468" }
```

只要有一个人配了 pin，页面就会先弹登录（选人 + PIN），之后所有请求只能以本人身份
提问、交卷、看档案（导师看板仍可一屏看全员进度）。不想用了把 pin 删掉即恢复开放，
改动立即生效、无需重启。

## 2. 它解决导师的什么麻烦

导师说"每届都培养太麻烦了"，他烦的不是回答问题，是**重复劳动**。重复劳动有 5 种：

| 重复劳动 | 传统做法 | 这个工具怎么接过去 |
|---|---|---|
| 信息传递 | 同一批问题问一百遍 | 知识问答（**答案强制带出处**） |
| 路径规划 | 反复讲培养计划 | 成长地图闯关，导师只定一次关卡 |
| 陪练反馈 | 逐句改、逐行 review | 陪练室角色扮演 + AI 评分，消耗算力不消耗导师 |
| 进度追踪 | 挨个问"你到哪了" | 成长档案 + 导师看板停滞预警 |
| 情绪与融入 | 当心理疏导员 | 支持匿名提问，低门槛入口 |

外加一条关键机制：**FAQ 自动沉淀闭环**——同一问题被问两次，自动生成 FAQ 草稿，
导师一键确认后入库，下一届同类问题就不再打扰他。**工具越用越省力。**

## 3. 八个模块

**新人侧**

| 模块 | 说明 |
|---|---|
| 🔧 环境自检 | 配置化检查命令/路径/环境变量/端口，失败项直接给修复步骤 |
| 📋 任务中心 | 导师按需求把任务**拆成多个子项**（问题回答 / 需求 / 其他），带资料附件；新人逐项反馈（文字+附件），导师逐项确认，进度一目了然 |
| 🗓️ 周报 | 提交周报 → 按「周报标准」自动批改打分并计入成长记录；历史与全员列表，导师不用挨个追问进度 |
| 💬 问答助手 | AI + 知识库回答，**每个答案附出处**；没答好可一键「联系导师」，导师的回复直接回到问答页 |
| 🗺️ 成长地图 | 每关「学 → 练 → 考」，考过 80 分解锁下一关；研发/非研发各一套 |
| 🎭 陪练室 | AI 扮演客户/评审人/技术负责人，多轮对话后按评分标准逐维度打分 |

| 📈 我的档案 | 能力雷达（对岗位基线，不做人际排名）+ 成长记录 |

**导师侧**

| 模块 | 说明 |
|---|---|
| 🎯 导师看板 | **极简三件事**：回复新人问题、收新人消息与周报（一键导出文件）、项目知识库管理 |
| 📚 知识库 | 每条知识带责任人和复核日期，过期标红；FAQ 沉淀草稿在这里确认发布 |
| ⚙️ 设置 | 大模型配置（可选）+ 检索阈值 |

## 4. 导师最关心的：怎么改知识库

**不需要写代码，改文本文件就行。** 改完刷新页面立即生效（无需重启）。

### 加一条知识 → `data/knowledge/` 下新建 `.md`

```markdown
---
id: kb-eng-005
title: 灰度发布怎么做
track: engineering, general
tags: 发布, 灰度, 流程
owner: 张伟
review_date: 2027-06-30
source: 工程规范 v2
---

正文写 Markdown 就行。

## 小标题也支持

- 列表
- 表格
- `代码`
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一标识，被引用时用到 |
| `title` | 是 | 检索权重最高，请写成人会怎么问 |
| `track` | 否 | `engineering` / `non_engineering` / `general`，逗号分隔 |
| `tags` | 否 | 逗号分隔，也参与检索加权 |
| `owner` | **强烈建议** | 知识责任人。过期时看板会提醒他复核 |
| `review_date` | **强烈建议** | 复核日期。**过期会在导师看板标红**，防止半年后开始教错东西 |
| `source` | 否 | 出处，会显示在答案下方 |

### 加一条 FAQ → `data/faq.json` 的 `items` 里加一项

```json
{
  "id": "faq-021",
  "q": "公司健身房在哪里？",
  "a": "在 B 座 3 层，工作日 7:00-22:00 开放。",
  "track": ["general"],
  "tags": ["福利"],
  "owner": "行政部",
  "review_date": "2027-06-30",
  "source": "行政手册",
  "status": "published",
  "created_by": "manual"
}
```

`status` 必须是 `published` 才会进入检索池；`draft` 是待导师确认的自动沉淀草稿。
命中次数由系统自动统计（存运行数据 SQLite，不再写进 `faq.json`），正常使用不会弄脏这个文件的 git diff。
> ⚠️ 答案还是「待补充」占位内容的草稿**会被拒绝发布**——发布出去就会被当正式答案自动回复给新人。

### 改关卡地图 → `data/paths/engineering.json`

每关的结构：

```json
{
  "id": "e7",
  "name": "第 7 关 · 性能优化",
  "window": "Week 13-16",
  "goal": "能定位并解决一次真实的性能问题",
  "requires": ["e6"],
  "learn":     [{ "title": "性能排查手册", "type": "kb", "ref": "kb-eng-005", "minutes": 30 }],
  "practice":  [{ "title": "练习「线上事故复盘」", "type": "coach", "ref": "sc-eng-incident" }],
  "exam": {
    "pass_score": 80,
    "questions": [
      {
        "id": "e7q1",
        "q": "题干",
        "options": ["A", "B", "C", "D"],
        "answer": 0,
        "dimension": "professional",
        "explain": "解析，答完会展示给新人"
      }
    ]
  }
}
```

- `answer` 是**选项下标**（从 0 开始）
- `dimension` 取值：`business` / `professional` / `communication` / `discipline`
- `requires` 写前置关卡 id，留空数组 `[]` 表示一开始就能做

### 改评分标准 → `data/rubrics/*.json`

每条评分项里的 `signals` 是给**未接入大模型时**的本地启发式评分用的，
也是导师校准 AI 打分口径的地方：

```json
{
  "id": "risk",
  "name": "风险与边界",
  "weight": 25,
  "probe": "这个改动最坏的情况下会出什么问题？你怎么兜底？",
  "levels": { "1": "完全没考虑异常", "3": "提到主要异常", "5": "覆盖边界、并发、回滚与监控" },
  "signals": {
    "good": ["边界", "异常", "回滚", "兜底", "监控"],
    "bad":  ["不会出问题", "应该没事", "没考虑"]
  }
}
```

### 改陪练场景 → `data/scenarios/*.json`

关键字段：`role`（AI 扮演谁）、`brief`（背景交代）、`opening`（开场白）、
`rubric`（用哪套评分标准）、`max_turns`、`model_answer`（满分示范，评分后会展示给新人）。

### 改环境自检 → `data/env_checks/*.json`

四种检查类型：

| type | 作用 | 关键字段 |
|---|---|---|
| `command` | 执行命令看输出 | `cmd`, `expect` |
| `path` | 路径是否存在（支持 `%USERPROFILE%` 这类变量） | `path` |
| `env` | 环境变量是否配置 | `var`, `expect` |
| `tcp` | 主机端口是否可达 | `host`, `port`, `timeout` |

> ⚠️ 种子数据里的内网地址（`10.0.0.1`）是**占位示例**，请替换成贵司真实地址，否则会永远显示不可达。

### 调整"必须转人工"的敏感话题 → `core.py` 顶部

分两档，这个区别很重要：

- `HARD_PATTERNS`：**知识库有也不答**，一律转人工。适用于答案依赖个人情况、答错不可逆的话题（薪资、绩效、离职、社保、法务）。
- `SOFT_PATTERNS`：**知识库有就照文档答**，并附一句"动手前请再向导师确认"；知识库没有才转人工。适用于权限、生产库、密钥、报销这类公司本来就有标准流程的事。

> 第一版把「权限」也放进了一刀切名单，结果"怎么申请软件权限"——FAQ 里明明写了流程——也被推给导师，
> 与"减少导师重复劳动"的目标正好相反。所以必须分档。

### 调整检索的严格程度 → 页面「设置」或 `core.py` 的 `DEFAULT_SETTINGS`

| 参数 | 作用 |
|---|---|
| `match_threshold` | 词覆盖率正常时的最低相关度 |
| `strong_threshold` | 词覆盖率偏低时改用的更高门槛 |
| `min_coverage` | 覆盖率的临界值 |
| `draft_trigger_count` | 同一问题被问几次后自动生成 FAQ 草稿 |

调完请跑 `python smoke_test.py`——里面的「检索标定回归」段落会告诉你有没有调坏。

## 5. 可选：接入大模型

**不填也能用**。未接入时：
- 问答 → 直接返回知识库原文 + 出处（可信优先，宁可少说也不错说）
- 陪练 → 切换为「结构化引导自省模式」，按评分标准逐条追问并给自查清单
- 批改 → 使用可解释的本地启发式评分，并标出"AI 拿不准"的条目

填了之后以上三处自动升级为模型生成：

```powershell
$env:MENTOR_LLM_BASE_URL="https://api.deepseek.com/v1"
$env:MENTOR_LLM_API_KEY="sk-xxxx"
$env:MENTOR_LLM_MODEL="deepseek-chat"
python server.py
```

任何 **OpenAI 兼容**接口都可以（DeepSeek / 通义 / 智谱 / vLLM / Ollama 的兼容层）。
也可以在页面「设置」里填，保存在 `data/runtime/settings.json`（不会进版本库）。

> 接了模型之后，答案会被强制要求标注 `[1][2]` 来源编号，并且系统提示词里
> 明确禁止使用"你自己的通用知识补充事实"。模型不听话也没关系——**出处是给新人自己核对的**。

## 6. 自检

```powershell
python check_data.py   # 校验全部内容文件（改完知识库后跑一下，不需要启动服务）
```

改了 `data/` 里的任何文件后建议先跑这个。它会检查：JSON 能不能解析、必填字段、
id 有没有重复、考题的 `answer` 是不是合法选项下标、`requires` 指向的关卡是否存在、
评分项权重合计是不是 100、陪练场景引用的评分标准是否存在……

> **为什么这个很重要**：`faq.json` 里少一个逗号，程序不会崩，
> 只会把整个 FAQ 当成空的加载了——工具照常运行，只是"静默变傻"。
> 所以服务启动时也会在控制台打印问题，页面侧边栏也会常驻提示。

```powershell
python server.py       # 先启动
python smoke_test.py   # 另开一个终端
```

80 项端到端行为验证，包括：命中给出处、知识库没有时转人工、HARD 敏感话题无条件转人工、
SOFT 敏感话题照文档答并附提醒、**12 条检索标定回归用例**、知识库外的 10 个问题零误答、
全对才能通关、通关才解锁、陪练能评分、FAQ 沉淀闭环端到端跑通。
测试可以重复运行，跑完会自动清理自己写进知识库的数据。

## 8. 从零整理知识：三天手册

材料全是空白时，按这个顺序做，别追求完美：

- **第 1 天上午**：坐在导师旁边，把他过去半年被新人问过的问题**全部记下来**（翻聊天记录最快），目标 50 条。
- **第 1 天下午**：写成 `faq.json`，每条补 `owner` 和 `review_date`。写得短、写得糙都行，先有再优。
- **第 2 天**：把导师最烦的 3 件手工活变成自检脚本 / 批改 rubric / 陪练场景。
- **第 3 天**：找一个新人真实用一天，记录"AI 没答上来的问题"——那就是下一批知识条目。
  （工具已经把这些问题自动收集在看板的「沉淀候选池」里了。）

## 9. 拿什么指标去跟导师汇报

1. **导师每周被重复提问的次数** —— 目标下降 70%
2. **新人从入职到能独立交付首个任务的天数** —— 目标缩短 30%
3. **知识库自动沉淀的条目数** —— 每届 ≥ 50 条

## 10. 几个刻意做进去的取舍

| 决策 | 为什么 |
|---|---|
| 检索不达标就转人工，而不是硬答 | 培养场景里错误答案的代价远大于多问一句 |
| 敏感话题分 HARD / SOFT 两档 | 一刀切会把"怎么申请权限"这类有标准文档的问题也推给导师，反而增加负担 |
| 内容文件必须做校验和编码容错 | 打错一个逗号会让工具"静默变傻"，比崩溃更危险；记事本存 UTF-8 会加 BOM |
| 提问**不**参与能力打分 | 用提问频次打分会诱导新人少问问题，与目标相反 |
| 导师看板不做人际排名 | 排名会引发抵触和内卷，只比个人 vs 岗位基线 |
| 成长档案对新人本人完全可见 | 单方面监控必然引发反感 |
| 知识必须带 owner 和复核日期 | 否则半年后 AI 会一本正经地开始教错东西 |
| 未接模型时功能退化为"可用"而非"不可用" | 小工具大概率一开始没有 API Key，不能因此变成废物 |
| 纯标准库、零依赖 | 要能在任何一台内网机器上 `python server.py` 活下来 |

## 11. 技术选型建议（如果要扩大规模）

当前形态适合**一个团队、一届新人、个人或小组自建**。出现以下需求时再升级：

| 需求 | 建议方案 |
|---|---|
| 要发全组用、要账号体系 | FastAPI + 前端框架 + 正式数据库 |
| 要更高的问答准确率 | 知识量大到几千条时，接入本地向量库（Chroma/Milvus）+ 重排模型 |
| 要入口更自然 | 接飞书 / 企业微信机器人（提问、周报推送、停滞预警） |
| 有数据安全要求 | 全部本地模型（Ollama / vLLM 内网部署） |
| 要让回答"像某个导师" | 用该导师的历史回答做 few-shot，并保留"转人工"阈值 |
