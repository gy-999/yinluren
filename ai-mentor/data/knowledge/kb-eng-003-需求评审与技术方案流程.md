## 完整链路

```
需求提出 → 需求评审 → 技术方案评审 → 开发 → 自测 → 联调 → 提测 → 上线 → 复盘
```

## 需求评审（你做新人时主要参与这一环）

参会：产品、研发、测试、必要时运营。

研发在会上的职责不是"听需求"，而是当场确认四件事：

1. **目标**：这个需求要解决谁的什么问题？不解决会怎样？
2. **范围**：本期做什么、明确不做什么。
3. **验收标准**：怎么算做完了，能不能量化。
4. **时间点**：期望上线时间，以及为什么是这个时间。

> 如果这四件事会上没确认清楚，**你有权要求会后补充书面说明**，而不是先开工再返工。

## 技术方案评审

- 方案文档提纲：背景 → 目标 → 方案对比（至少两个候选）→ 选定理由 → 数据模型/接口 → 异常与边界 → 回滚方案 → 工作量拆解。
- 方案里**必须**出现"如果出问题怎么回滚"。
- 涉及数据变更的，必须说明兼容策略与灰度方式。

## 上线与复盘

- 上线前确认：监控有报警、有回滚路径、有值班人。
- 上线后 24 小时内观察核心指标。
- 出现 P2 及以上问题，3 个工作日内出复盘，复盘只对事不对人。
